# 三色分級判斷邏輯(草稿,閾值待驗證)

## 設計原則
採用「**任一硬指標觸發即降級**」的邏輯,而非加權平均——安全類產品寧可保守,不做「數值互相抵銷」的平均計算。

## 判斷架構(草稿)

```
若符合以下任一條件 → 紅色(危險,勿下水)
- 豪雨特報 / 強風特報 / 雷雨特報 生效中
- 波高超過閾值(待訂,需參考戲水安全標準)
- 颱風警報生效中

否則,若符合以下任一條件 → 黃色(需注意)
- 風速偏高(未達特報等級但明顯偏強)
- 波高中等
- 處於潮汐交替時段(滿潮/乾潮前後)

否則 → 綠色(適合下水)
```

## 監測要素與資料來源對應

| 要素 | 資料來源 | 用途 |
|------|----------|------|
| 波高 | 海象環境資訊平台(西子灣逐三小時海象預報) | 主要危險判斷 |
| 海面風速 | 海象環境資訊平台 / 氣象開放平臺 | 危險判斷 + 特報連動 |
| 潮汐(漲退潮時刻) | 潮汐預報(鼓山測站) | 提醒滿潮/乾潮交替危險時段 |
| 海溫/氣溫/體感溫度 | 西子灣海水浴場頁面資料 | 舒適度參考,非安全判斷主因 |
| 天氣特報(豪雨/雷雨/強風) | 氣象開放平臺 | 直接觸發紅色警示 |
| 離岸流風險 | 無現成 API,需搭配潮汐+風向推算 | 進階功能,MVP 階段先跳過 |

## 重要提醒(來自安全責任討論)
- **閾值不可憑感覺自訂**,需要有依據來源,例如:
  - 水域遊憩管理相關辦法
  - 各縣市水域公告標準
  - 海洋運動專家/救生單位意見
- 這是產品可信度的地基,也是免責聲明能站得住腳的前提
- App 內須明確標示:「本 App 僅供參考,實際下水請以現場狀況及救生員指示為準」
